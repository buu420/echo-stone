# Echo Stone 0.1.0 coverage

Echo Stone 0.1.0 beta supports the Windows x64 Steam build 18789511.
Source and research were compared with the user's Fighting Chance 0.6.0 and
FighterZAccess r6 projects. Each game's offsets and layout were researched
independently.

Model tests do not prove the native fields are present in a particular live
menu. Static analysis does not prove all audible narration, gameplay, online
behavior or controller compatibility. Unmapped screens and character-specific
special mechanics are not claimed supported. No hidden resource, prediction,
automation or gameplay-state writes are provided.

Team-preset member names come from the portraits actually drawn, including the
game's fallback portraits. Save-data getters are not called: Ghidra showed writes
inside them. Stone names use live localized text when resident and a
six-entry, material-verified English map for this English install otherwise.
Unresolved character text and random placeholders never reveal a concealed ID.
Keyboard bindings currently use engine key names (such as SpaceBar); unrecognized
controller glyphs are described as a button icon. Handicap requires its drawn
index to match the focused level. These limits are not full glyph/artwork coverage.

Missions never reads completion bits or descriptions from save/data tables. When
details are hidden, its mission number is derived from the drawn cursor and
visible slot chip. Tutorial descriptions read the shown platform's actual text
and Images in slot order, skipping layout spacers and joining wrapped lines.
The ten previously verified controller glyph material names are resolved,
plus the observed PC/Steam Dir and Sti materials as directional controls and
analog stick. Other glyphs remain a neutral button icon.
The active Mission reader uses the current fight's tutorial and HUD owners.
The legacy `WD_MissionSelect` path remains unobserved.

The pinned Prism x64 library advertises speaking-status support on this machine's
NVDA backend, and a nonaudible query returned success. Delivery uses that status
with a short startup grace interval; other backends use the reference mod's text
pacing. This does not establish that every game line has been heard completely.

The protected game's first deferred-loader startup did not initialize the ASI.
The reviewed compatibility configuration passed the actual pinned-loader host
fixture and then loaded ASI/Prism in-game. The exact-code hook attached and
capture counts advanced without exceptions. This is startup/menu evidence, not
a combat performance or controller test.

The live trace also exposed a designer-placeholder dialog frame. A regression
now requires the visible body to match the message copied by SetupWindow before
it becomes readable, while continuing to block underlying menus. That repair
is installed in Candidate 4; its first startup attached without capture errors.

A subsequent live title test exposed numbered reflected names. Unreal stores
the field TextBlock_213 as base TextBlock plus number 214; property lookup had
omitted that suffix. Exact full-name lookup now passes native/selection/combat
regressions and the same external C++ reader captures the displayed PRESS ANY
BUTTON immediately. Candidate 5 installed this repair and Prism accepted the
title prompt in-process; listener confirmation for that title line is pending.

The user identified an Xbox Wireless Controller for the D-pad report. A bounded
five-minute read-only trace found no active XInput controller and all four native
UI pad masks stayed zero. That does not establish the cause of the earlier
navigation report. A connected-controller test remains necessary; no controller
settings, input mappings or game input were changed by the agent.

The next trace did capture native keyboard menu input and IndexFocus changing
4 to 5 and back to 4 in an enabled, focused Unreal window. The reader was silent
because it relied on FocusFlag, which the Blueprint clears after an entry
animation. Main capture now follows the persistent IndexFocus and validates its
rendered row, active-menu ownership and input gate. The failing live state was
reproduced in a regression before the correction. Updated in-process menu
narration was confirmed by the user in Candidate 6, including Options. Character
Select and Collection subsequently exposed separate coverage gaps, tracked in
the table above. The new FName repair passed native, selection and combat
regressions and a passive native Character Select check. Single-controller
Training menus now follow their sole active input side independently of combat
tracking. After the game closed, all 13 offline suites passed, including the
deployment fixture. The user subsequently confirmed normal close and approved
installation without launching. Candidate 7 updated the ASI and README, matched
all 10 installed payload hashes and preserved all 23 current executable/save
records. In-game listening checks remain deferred; the game was left closed.

Collection uses the flow's current widget and declared open child, not retained
background lists. Late ownership, serial, focus-slot and world changes discard
the capture. Modal dialogs retain priority. The model viewer's separate bound
text fields and the artwork viewer's visible control guide remain readable when
their normal titles are hidden; hidden titles/profile placeholders are not read.
Control-action text is covered; full controller glyph mapping remains subject
to the limits above. Playback progress is not captured.

Installation waits for the user's deliberate game-close confirmation. Original
files and saves must be checked after the installer exits. No manifest reader
should run while installation is active.

The current Story/loading update is detailed in `story-accessibility.md`.
